Both maintainers are listed in [`.github/CODEOWNERS`](.github/CODEOWNERS), so
every pull request requests review from them automatically.

## What a maintainer does

- Reviews and merges pull requests. A change is merged by someone other than its
  author; see [CONTRIBUTING.md](CONTRIBUTING.md).
- Responds to security reports under [SECURITY.md](SECURITY.md).
- Cuts releases, which are prepared automatically by release-please and merged
  like any other pull request.

## Becoming one

There is no formal ladder yet — the project is small enough that it would be
ceremony. Sustained, reviewed contributions and a willingness to take on the
review load are what count. Open an issue, or say so on a pull request.

## Decisions

Two maintainers, so decisions are made by agreement. Where we disagree and it
matters, the change does not land. Anything that changes the project's direction
belongs in an issue before it belongs in a pull request.
